## 定向回归

`tests/Test-Game1202Compat.ps1 -ProjectPath <恢复工程> -Godot <游戏对应引擎>`

实际加载游戏 Main、Player 和 Friends 扩展，通过原生宝箱信号调用房主发送端，消息经过 JSON 往返，再调用生产接收端。使用不同随机种子验证突变发生/未发生、连续突变及瘤累加、武器空槽和满槽合成、重复消息、旧消息、波次过期、最近突变标记和本波上限恢复。满血拾取将生产远端镜像与真实 Player 逐项对比属性、Extra Stomach 追踪和波次计数，包含剩余 1、到顶、刚好够、无上限、未满血和多个独立效果。

修复前对照：41 项检查中 20 项失败；首次修复后同组 41 项全部通过。新增波次上限断言随后暴露 JSON 数字类型问题，修正整数恢复，并补充无尽模式商店完整库存检查。最终 **54/54 项通过**，包含标记、波次上限、协议握手及迟到宝箱的库存保障。

## LAN 回归

`tests/Test-WaveSettlementLan.ps1 -Mode compat -ProjectPath <恢复工程> -Godot <游戏对应引擎>`

沿用真实 ENet、原生奖励队列和客户端领取按钮。测试扩展仅为原生领取设置不同端随机种子并记录调用次数；要求房主调用一次、客户端零次，恰好一份宝箱道具、一次瘤突变和进化 -10→-11，两端完整突变效果相同。其余波次场景继续验证延迟结算、重复回调和重复消息。

此次同时落地此前隔离验证的夹具修正：单账号 LAN 禁用 Steam 建房（已有 Local-InputProbe，ENet 未替换）、读取退出码前 WaitForExit/Refresh、商店模拟消息唯一 action_id、按新版瘤语义验证突变、Windows IPC 原子改名有限重试。没有重试玩法动作或降低断言标准。

最终 **24/24 个回归场景通过**：定向检查、Steam 初始化 API double、重试/恢复/商店协议、LAN 购买/个人商店/机械升级、1+3 与 2+2 席位、七种波次结算场景，以及零售装备效果、效果生命周期和机械升级。零售装备四个场景各 75 项、生命周期两个场景各 92 项通过。

验证使用 Brotato 1.2.0.2、安装版 Godot 3.7.dev.custom_build.74e86be54；零售测试同时加载 NoobsWantToLive 1.1.5 和 FiveItemShop 1.1.4。完整结果、首次失败和重试日志位于工作区 `work/compat-fix-1202-20261113`，最终明细为 `final-results.json`，源码哈希为 `final-frozen-source.json`。测试采用本机独立进程，不能替代跨机器 Steam P2P 和实体手柄验证。
